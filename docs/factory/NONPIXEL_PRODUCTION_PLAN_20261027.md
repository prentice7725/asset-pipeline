# 넌픽셀 생산 파이프라인 우선 계획 — 2026-10-27

사용자 결정: 픽셀 경로는 연구과제로 두고, 넌픽셀 파이프라인을 우선 구축한다.
기준 커밋 `cc2c5d6`; 이 문서는 개발 우선순위이며 운영 활성화나 품질 승인 기록이 아니다.
기존 픽셀 코드·후보·실험 근거는 보존한다. 픽셀 연구 완료를 넌픽셀 출시 조건으로 두지 않는다.

## 생산 목표

- 정지 이미지: Brief/참조 → 명시한 Provider → 원본 보존 → 기본 QA → 리뷰 패키지.
  정지 결과만으로 작업을 끝낼 수 있어야 한다.
- 애니메이션: 기존 정지 결과를 명시적으로 선택 → I2V 또는 기존 영상 입력 →
  원본 영상 보존 → 프레임 추출 → 알파·정렬 → 명시적 루프 선택 → 아틀라스 →
  Godot/Phaser 임포트 → 사람 리뷰.
- 실행 계약·해시·예산·실패 상태·출력 검증은 공유한다. 넌픽셀 출력에 64px·24색
  Pixel Gate를 강제하지 않는다. 알파, 외형 유지, 프레임 순서, 피벗과 시간은 별도로 검증한다.
- SFX는 기존 독립 경로를 유지한다. 픽셀 연구를 자동 대체 경로나 실패 복구로 연결하지 않는다.

## 구현 순서와 수용 기준

1. **넌픽셀 진입점 연결.** 기존 Factory motion job과 생성 예산 조정자를 재사용해
   사용 가능한 명시적 경로를 일반 생산 진입점과 연결한다. 지원 입력과 연구/운영 상태를
   일관되게 표시한다. IMAGE_ONLY는 영상 호출 없이 종료하고, 모션 실패·중단 후에도
   원본 정지 이미지와 완료 상태가 보존되어야 한다. 외부-only·2/3장·미지원 모션은
   Provider 호출 전에 차단한다. 새 기본 활성화나 MCP 도구 추가는 하지 않는다.
2. **재처리와 품질 리뷰 고정.** 원본 영상과 설정을 고정한 재처리에서 순서·FPS·피벗·
   출력 해시를 검사한다. 기존 알파/루프 레시피와 모든 중간 파일을 보존하고, 밝은/어두운
   배경에서 흰 내부 영역 손실·외곽 잔상·장비 변형·시작/끝 연결을 검토한다.
   사람의 프레임/알파 선택을 자동 승인으로 대체하지 않는다.
3. **실제 게임 임포트 검증.** 기존 native Godot/Phaser 출력을 재사용한다. 가만히 재생하는
   임포트뿐 아니라 실제 사용 프로젝트의 크기·이동 속도·발 접지·피벗·반복 주기를 확인한다.
   테스트용 이동 화면만으로 접지나 game-ready를 승인하지 않는다.
4. **공통 진입점 실생성 검증.** 앞 단계의 오프라인 코드·음성/정지 회귀가 통과한 뒤,
   별도 명시 예산으로 정지 후보 → 같은 참조 해시의 영상 → 출력·리뷰 패키지를 확인한다.
   기존에 소비한 승인/예산을 재사용하지 않는다. 재시도·Provider fallback은 자동 실행하지 않는다.
5. **참조 2·3장 확장.** 먼저 Provider의 수·역할 지원을 확인하고, 각 참조가 실제 입력에
   소비된 근거와 정체성/포즈 유지 결과를 확보한다. 한 장 입력이 안정되기 전에 범위를 넓히지 않는다.

## 완료 판정

정지 생성과 모션 후속 작업을 각각 끝내거나 이어갈 수 있고, 실패로 이미 끝난 정지 작업이
손상되지 않으며, 원본·예산·변환·QA를 추적할 수 있어야 한다. 엔진에서 실제 소비한 증거와
사람의 미술/애니메이션 리뷰를 구분해 기록한다. `REVIEW_REQUIRED`, `game_ready=false`,
Golden/SOT 및 운영 활성화 게이트는 실제 승인 전까지 유지한다.

이번 변경은 문서만 수정한다. 기존 픽셀 registry의 상태를 자동 변경하거나 구현을 삭제하지
않으며, 라이브 MCP 교체·모델 설치·생성을 수행하지 않는다. 롤백은 이 문서와 우선순위 링크를
되돌리는 것으로 끝난다. 기록 보존과 기존 정지 이미지·SFX 경로는 계속 유지한다.
