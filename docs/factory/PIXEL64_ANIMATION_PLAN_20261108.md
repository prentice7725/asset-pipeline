# Pixel64 애니메이션 계획 (2026-11-08)

사용자 결정(2026-11-08): 승인된 64px Static Master에서 애니메이션을 만드는 경로를 연다. 방식은
"모션 영상에서 프레임 뽑기"다(포즈 편집, 사람이 그리기 대신). 첫 동작은 walk 하나다.

## 범위

- 대상: [Pixel64 생산 경로](PIXEL64_PRODUCTION_PLAN_20261107.md)로 승인된 64×64 PIXEL_STATIC 캐릭터 마스터.
- 영상: 이미 설치된 로컬 MiniMax H3 R2V 그래프(`config/workflows/deno_minimax_h3_r2v_8step.json`, 768×768,
  56프레임, 24fps). 로컬 GPU라 유료 호출이 없다.
- 새 코드만 쓴다. 레거시 `_ported` 코드와 기존 PIXEL_ANIMATION 경로(파란 튜닉 `blue_tunic_white_matte_v1`
  프로필, 8위상 walk)는 바꾸지 않는다. 그 프로필을 64px 캐릭터에 쓰지도 않는다.
- 32px은 계속 동결이다. idle·attack은 이 계획 밖이다(walk가 끝난 뒤 별도 결정).
- 새 레지스트리 항목은 EXPERIMENTAL, explicit_only다. MCP 도구는 여섯 개 그대로이고 스키마를 바꾸지 않는다.
- 생성은 예약한 run마다 한 번이다. 재시도·대체 경로는 없다. 검증 생성은 기록만 하면 횟수 제한이 없다
  (2026-10-29 결정). 실패한 게이트는 원인을 고친 뒤 별도 run으로만 다시 한다.
- 결과는 후보다. 사람이 Aseprite에서 검토하기 전에는 승인되지 않는다(HUMAN_REQUIRED).

## 흐름

```text
승인된 64px Static Master (approval_record.json)
→ A1 레퍼런스: 마스터를 정수 배율 nearest로 키워 흰 배경 768×768에 놓는다
→ A2 영상: MiniMax H3 R2V 한 번 (walk 프롬프트, 고정 seed)
→ A3 프레임 선택: 접촉 시트를 보고 사람이 위상별 프레임 번호를 고른다(selection.json, reviewed_by)
→ A4 픽셀화: 프레임마다 피사체 상자 → 마스터와 같은 높이로 축소 → 발 기준선 정렬 → 64×64
          → 마스터 팔레트로 고정 → 이진 알파
→ A5 검사: 프레임별 Pixel Gate(마스터 팔레트), 정체성·흔들림 보고서
→ A6 납품: Aseprite 태그 `walk` 왕복, Godot/Phaser 내보내기, 리뷰 아틀라스
→ 사람 검토 (Aseprite) → 승인 기록
```

## 단계

### A0. 캐릭터 마스터 승인 (사람)

지금 승인된 마스터는 동전·열쇠 같은 소품뿐이다. 채택한 캐릭터 하나를 `review-resolution` →
`export-static` → Aseprite 확인 → `approve-static --transparent`로 승인한다. 걷기를 보려면 측면이나 3/4 측면
캐릭터가 낫다. 정면 캐릭터는 다리 교차가 잘 안 보인다.

### A1·A2. 레퍼런스와 모션 영상

- 레퍼런스는 승인된 마스터의 해시를 기록하고, 배율·여백·배경색을 manifest에 남긴다.
- 영상 run은 그래프 해시, 모델 이름, 프롬프트, seed, 레퍼런스 해시를 기록한다. 영상 파일은 workspace에만 둔다.
- 생성 전에 승인 기록을 `validate_approval`로 다시 확인한다. 승인이 없거나 바뀌었으면 제출하지 않는다.

### A3. 프레임 선택

- 도구는 접촉 시트(번호가 붙은 축소 프레임)만 만든다. 위상 판정은 사람이 한다.
- 64px walk는 위상 수를 선택 파일에 명시한다(4·6·8 중 하나, 기본 8). 프레임 번호는 시간 순서이고 중복이 없어야 한다.
- 선택 파일은 원본 영상 해시를 가리킨다. 다른 영상과 섞이면 거부한다.

### A4. 64px 픽셀화

- 배경색과 허용 오차로 피사체 상자를 찾는다. 모든 프레임에 같은 배율을 쓴다(마스터의 피사체 높이 기준).
  프레임마다 배율을 바꾸면 크기가 흔들린다.
- 발 기준선(피사체 맨 아래 줄)과 가로 중심을 마스터에 맞춘다.
- 색은 마스터 팔레트의 가장 가까운 색으로 고정한다. 새 색은 만들지 않는다. 투명 처리는 Pixel64 투명 납품과
  같은 규칙(이진 알파, 갇힌 영역은 검토 항목)을 쓴다.

### A5. 검사 (기계는 보고만, 판정은 사람)

- Pixel Gate: 64×64, 마스터 팔레트 안의 색만. 실패하면 이후 단계로 가지 않는다.
- 정체성: 프레임마다 마스터와의 팔레트 사용 비율 차이, 피사체 높이·너비 변화.
- 흔들림: 기준선·가로 중심 이동 픽셀 수, 이웃 프레임 사이 바뀐 픽셀 비율.
- 기준값은 첫 실제 run에서 잰 뒤 정한다. 그 전에는 숫자만 기록하고 통과/실패를 매기지 않는다.

### A6. 납품과 검토

- 기존 `AsepriteProvider.export`로 `walk` 태그 마스터와 시트를 만들고 RGBA 일치를 확인한다.
- Godot/Phaser 내보내기는 기존 `assetpipe.motion.exports`를 쓴다(새 엔진 형식을 만들지 않는다).
- 상태는 `EXPORT_READY_REVIEW_REQUIRED`에서 멈춘다. 애니메이션 승인 기록은 사람이 Aseprite에서 확인한 뒤에만 쓴다.

## 구현 순서

1. A4·A5 오프라인 먼저: 합성 프레임으로 픽셀화·검사·내보내기를 테스트한다. 생성 0회.
2. A0: 사용자가 캐릭터 마스터 하나를 승인한다.
3. A1·A2: 레지스트리 항목과 레퍼런스·영상 제출. 실제 영상 한 번.
4. A3 → A6: 그 영상으로 끝까지 실행하고 수치를 기록한다. 사용자가 Aseprite에서 판정한다.
5. 결과에 따라 기준값을 정하거나, 다른 캐릭터나 seed로 별도 검증 run을 계획한다.

## 하지 않는 것

- 프레임별 독립 생성, 프레임 보간, 자동 위상 판정.
- 영상 모델 교체나 유료 클라우드 영상.
- 기존 PIXEL_ANIMATION 경로, 레거시 코드, 파란 튜닉 프로필 수정.
- MCP 도구 추가, 공유 런타임 교체(별도 확인).
